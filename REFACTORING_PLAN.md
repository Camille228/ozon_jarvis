# План рефакторинга: Переход на FastAPI + Plotly Dash + PostgreSQL

## Главные правила работы (Контроль лимитов и контекста):
1. Работаем строго по фазам. Одна фаза = один крупный логический шаг.
2. После завершения каждой фазы — делаем коммит в Git.
3. После коммита останавливаемся и ждем моего подтверждения.
4. Ты сам решаешь, как разбить папки, какие создать файлы и как импортировать модули. Главное — соблюдать целевую архитектуру и не ломать текущую логику.

## Целевая архитектура проекта:
- `app/api/` — эндпоинты FastAPI
- `app/core/` — конфигурация и подключение к БД (SQLAlchemy)
- `app/models/` — ORM модели БД (PostgreSQL)
- `app/schemas/` — Pydantic-схемы для валидации
- `app/repositories/` — слой работы с базой данных (CRUD)
- `app/services/` — бизнес-логика (Ozon API, расчеты юнит-экономики)
- `app/main.py` — точка входа для FastAPI

## Фазы работы:

**Фаза 1: Фундамент и База Данных**
Перевести существующую логику на SQLAlchemy и PostgreSQL. Настроить `core`, `models` и `repositories`. Убедиться, что данные о товарах и логах успешно читаются и пишутся в новую БД.

**Фаза 2: Бизнес-логика (Services)**
Перенести работу с Ozon API и расчеты из старых скриптов в сервисный слой. Настроить фоновое обновление данных.

**Фаза 3: Создание FastAPI**
Написать REST API эндпоинты (получение товаров, статус, синхронизация), которые будут обращаться к сервисам.

**Фаза 4: Фронтенд на Plotly Dash**
Создать скелет Dash с поддержкой многостраничности. Перевести интерфейс со Streamlit на Dash, настроив связь с FastAPI через HTTP-запросы.

**Фаза 5: Финализация**
Очистить проект от старых файлов, обновить README, проверить работоспособность всей связки.
